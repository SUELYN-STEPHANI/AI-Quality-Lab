# Isaac — Search Relevance Grading

## Training Overview

Specialized training in Search Relevance Evaluation focused on determining
how effectively search engine results satisfy user intent.

The methodology goes beyond keyword matching.

The evaluator must understand what the user is attempting to accomplish,
analyze the scope of the query, identify the type of search result, validate
the result according to project rules and assign an appropriate satisfaction
rating.

---

## Core Evaluation Framework

The evaluation methodology follows the structure:

QUERY
↓
USER INTENT
↓
QUERY SCOPE
↓
RESULT TYPE
↓
REVIEW
↓
VALIDATE
↓
SATISFACTION RATING

The central evaluation question is:

> How well does this result satisfy the user's intent?

---

## 1. Query Analysis

Training in interpreting exactly what the user entered into the search engine.

The evaluator must avoid adding assumptions that are not supported by the
query.

Analysis considers:

- Query wording
- Named entities
- Knowledge terms
- Search context
- User location when relevant
- Query date when relevant

---

## 2. User Intent Analysis

A search query does not necessarily reveal the user's complete objective.

The evaluator must determine the most probable intent behind the search.

Skills include:

- Identifying dominant intent
- Identifying secondary intents
- Distinguishing probable from theoretically possible interpretations
- Understanding navigational intent
- Understanding informational intent
- Understanding product-related intent
- Applying contextual judgment

---

## 3. Query Scope

Evaluation of how broad or specific the user's request is.

The methodology considers a continuum between:

**Wider Scope ↔ Narrower Scope**

A broad query may reasonably support several different useful results.

A narrow query requires a result that satisfies more specific conditions.

The evaluator must therefore assess relevance according to the actual scope
of the request rather than simply matching keywords.

---

## 4. Result Type Identification

Training includes distinguishing different categories of search results.

Major result types include:

### Web / News Results

Content originating from websites, webpages or news sources.

These results require validation because publicly available web content is
not automatically accurate, current or appropriate.

### Information Card Results

Structured information generated from specialized data sources.

Examples may include:

- Weather
- Maps
- Sports
- Stocks

Different validation rules may apply depending on result type.

---

## 5. Result Review

Before assigning a rating, the evaluator examines what the result actually
provides to the user.

The evaluation cannot rely exclusively on:

- Result title
- Matching keywords
- Superficial similarity
- Initial appearance

The evaluator must determine whether the content itself fulfills the probable
user need.

---

## 6. Result Validation

The result is checked according to project-specific rules.

Validation may include:

- Content availability
- Language suitability
- Result accessibility
- Content accuracy
- Context
- Relevance
- Result type requirements
- Query/result relationship

The correct validation procedure depends on the type of result being
evaluated.

---

## 7. Satisfaction Rating

After research, review and validation, the evaluator assigns a rating based
on how successfully the result satisfies user intent.

The decision therefore considers the complete relationship:

**Query + Intent + Scope + Result + Context**

rather than simple textual similarity.

---

## Research → Review → Validate → Rate

The operational evaluation process can be summarized in four actions:

### RESEARCH

Understand the query and investigate additional context when necessary.

### REVIEW

Carefully examine the result presented to the user.

### VALIDATE

Check the result according to the applicable project rules.

### RATE

Determine how effectively the result satisfies user intent.

---

## Common Evaluation Errors

Training also focuses on avoiding common evaluator mistakes, including:

- Judging relevance only through keyword matching
- Inventing improbable user intents
- Ignoring query scope
- Assuming query length determines specificity
- Applying the same validation rules to every result type
- Rating before completing validation
- Confusing topical relationship with actual user satisfaction

---

## Quality Principles

### User-Centered Evaluation

Relevance is evaluated from the perspective of the person performing the
search.

### Evidence-Based Judgment

Ratings should follow the available evidence and project guidelines.

### Context Awareness

Location, date, query wording and result type may change the appropriate
evaluation.

### Consistency

Equivalent situations should receive equivalent treatment under the rubric.
